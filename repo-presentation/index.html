1. What CI and CD mean

Automation behind every push

CIContinuous IntegrationEvery time code is pushed, a server builds it and runs all the tests automatically. Nobody has to remember to.
CDContinuous DeliveryThe same pipeline packages a ready-to-run release when code reaches main.DEFINED, NOT YET IN USE: NOTHING RELEASED

2. Our pipeline

GitHub Actions

push→build→run all tests→save test report→✅ / ❌ on GitHub
Every push, any branchLinux gcc build and the full test suite, as a quick check.
Pull request into dev / staging / mainThe same on Linux gcc, Linux clang and Windows MSVC.
Reviewers hold a merge until CI is green; GitHub does not enforce it on our plan.

3. Why, and what's next

What it buys us

  • Bugs caught within minutes of the change that caused them.
  • No “works on my machine”: clean machines, several compilers.
  • Reviewers see test results on every PR.
  • A recorded history of what passed and failed.
Next
  • ASan and coverage jobs.
  • Server and GUI build jobs.
  • A release job: package noc_server with the GUI when main is tagged.
