1. What a test is

A small C++ function that checks a result

TEST(MeshTopology, Size_RowsColsAndRouterCount) { MeshTopology t(/*rows=*/3, /*cols=*/4); EXPECT_EQ(t.NumRouters(), 12); } TEST(MeshTopology, Constructor_RejectsEmptyDimensions) { EXPECT_THROW(MeshTopology(0, 4), std::invalid_argument); }
If a check fails, GTest reports:
the testthe lineexpected vs actual

2. How it fits our project

Built in, run automatically

No manual installCMake downloads GTest v1.14.0 at build time.
One folder per moduleCore/tests/ network, noc, topology, config… all built into one program, unit_tests.
Every test is its own entryOne ctest command runs the suite and names exactly which test failed.
Automatic on every changeGitHub Actions runs it on every push, and on Linux (gcc, clang) and Windows (MSVC) for every pull request.

ASan / UBSanNEXT
Does
Checks every memory access and stops at the exact line of a bad one.
Finds
Use-after-free (e.g. a flit reused after returning to the pool), out-of-bounds, leaks, integer overflow.
Added as
One compiler flag on the same tests, as an extra CI job.
Rollout
Report-only for 2–3 weeks while existing issues are fixed, then flag new ones.
Cost
Tests about 2× slower, in that job only.
LCovPLANNED
Does
Shows which lines the tests ran: an HTML report, green tested, red untested.
Finds
Untested code: error paths, corner cases, rarely used branches.
Added as
A coverage build in CI, with the report attached to each pull request.
Rollout
Informational first to set a baseline, then flag any drop in coverage.
Cost
A separate build; normal builds untouched.
